## Setup and data

Use Python 3.13. From the extracted archive:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The runner downloads the official train, validation, and test splits of
`EdinburghNLP/xsum` as Parquet files. The runner scans these files directly to avoid a second on-disk copy. Internet access is required
on the first run. Alternatively, pass `--data-dir` with local official Parquet files named `train.parquet`, `validation.parquet`, and `test.parquet`. Point `HF_HOME` to a writable cache directory if needed.
The code uses `document`, `summary`, and `id` for source, reference and
evaluation identity respectively.

For preparation of the two other Project 4 datasets, install the same dependencies
and use `load_dataset("abisee/cnn_dailymail", "3.0.0")` or
`load_dataset("knkarthick/samsum")`. CNN/DailyMail uses article and highlights,
with sentence splitting on articles and newline separation of highlights.
SAMSum uses dialogue and summary, with each dialogue utterance as a unit.
These datasets are listed for preparation only. This experiment uses XSum.

## One-command Docker run

```sh
docker compose up --build
```

Compose writes the experiment files to `runs/` on the host and retains the dataset
in a named Docker volume. The default run requests 16,384 training, 240
validation and 600 test examples before filtering. Use the local commands below to select a different run size.

## Run the experiment

```sh
python code/run.py all
```

To run the task entry points separately:

```sh
python code/run.py task1
python code/run.py task2
python code/run.py task3
```

Tasks 1 and 2 run independently. Task 3 requires their artifacts in the
same output directory and the same split settings. Set `--output` to use
a new directory for a different run. A limit of 0 means the complete split.
Split sampling uses NumPy PCG64 without replacement and preserves the official
order of the sampled rows. The fixed seed is 24 for split sampling, PyTorch initialization, and the first
epoch permutation. Each subsequent epoch uses 24 plus the zero-based epoch number.

## Quick end-to-end check

```sh
python code/run.py all --train 64 --validation 8 --test 8 --epochs 1 \
  --embedding 24 --hidden 24 --vocab-size 800 --source-limit 64 \
  --target-limit 16 --output runs/smoke
```

The smoke run checks the graph fit, one epoch of training, checkpoint load, beam
decoding, validation sweep, and matched test IDs. Its scores are for diagnostics.

## Outputs

The archive includes measured scores, file hashes and selected examples in
`results/experiment_results.json`. The following paths are generated by running
the code.

- `task1.json` stores split counts, validation settings and extractor test scores.
- `training.json` stores model settings and per-epoch loss and time.
- `task2.json` stores the full-article pointer-generator test scores.
- `task3.json` stores the validation sweep and matched test comparison.
- Prediction JSON files store the article ID, generated text, reference, and scores.
- `model.pt` contains the model, optimizer, configuration and vocabulary. Resume
  from the last completed epoch by passing `--resume` and a larger `--epochs`
  with the same output directory and original model and data options.
- `tfidf.pkl` is the fitted Task 1 vectorizer. Only load a pickle created by a
  trusted run.

Compression is output length divided by source length. Extractive density uses
greedy maximal matching fragments against the full article. The proxy measures
the fraction of output content word occurrences also found in the selected
extract for the same article. All scores are document averages.
